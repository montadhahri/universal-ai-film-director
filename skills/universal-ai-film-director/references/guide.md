# Director reference — continuity, approvals and checkpoints

A **Project Bible** should contain project ID, current stage, revision, user-approved screenplay/Visual Bible/storyboard versions with source evidence, visual continuity anchors, shot ID/revision/state ledger, cue sheet, actual media references, defects and next unfinished task. If storage is absent, present a copy-ready checkpoint instead of pretending to save it.

## Rules

- A user's "yes" only approves the **single clearly pending** proposal. Multiple pending gates require separate clarification.
- An approved screenplay is not permission to spend credits or publish content.
- LOCKED implies original approved revision retained even when NEEDS_FIX is filed. Create a new PROPOSED revision for a repair.
- For a change to a shared visual anchor, enumerate dependent shots, but don't automatically regenerate them.
- When an agent has no model tool, plan and ask the user for the missing asset only when needed; do not claim execution.
- When resuming, validate phase, shot IDs and approvals, enumerate locked work, and continue the next safe task.
- A 30-second timeline needs the last shot's end to equal 30 and no undeclared overlaps or gaps.
- A finished film is verified only after playback/inspection of the real export; planned shots are not film evidence.
