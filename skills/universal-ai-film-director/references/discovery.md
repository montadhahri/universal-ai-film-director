# Adaptive discovery and creative decision framework

Use with **the director decision procedure**.

## Ask less, learn more

Ask **exactly one question per discovery/decision turn**. Prefer the question
that resolves the highest-risk unknown for the current phase. Never ask for
information already confirmed in the Project Bible.

Typical order, adapted to context:
1. Story premise or personal experience (if not provided)
2. Audience and intended takeaway
3. Duration and distribution format
4. Tone, genre and emotional ending
5. Language, narration and dubbing needs
6. Visual references and constraints

If the user provides several answers at once, acknowledge all confirmed facts
and ask only the next unresolved question. Do not reset discovery.

If sufficient constraints exist for a useful first proposal, **do not ask another question just to complete a checklist**. However, for a personal, sensitive or autobiographical film, first identify whether the unresolved disclosure boundary, central emotional truth or intended audience meaning would materially change the screenplay. If so, ask one focused question about that pivotal unknown and stop; offer at most a clearly reversible short concept, not a detailed screenplay presented as settled. If those pivotal constraints are resolved, propose a coherent filmable interpretation or screenplay candidate and request approval of that exact version. Invite one focused decision only when it materially changes the creative direction. The Director should make constructive recommendations with a reason and trade-off; see [creative direction](creative-direction.md).

## Proposals versus approvals

A recommended default is **PROPOSED**, not APPROVED. If a user says "yes",
tie it only to the immediately preceding unambiguous question. If the question
contained multiple decisions, ask which decision was approved.

Use a short decision note:
```text
Confirmed: ...
Proposed: ...
Constraint / trade-off: ...
Next question (one only): ...
```

## Story development review

Evaluate logline, protagonist motivation, stakes, transformation, visual
storytelling, emotional contrast, runtime, and suitability for the audience.
Distinguish **creative advice** from hard constraints.

Do not invent biography, user emotions, workplace details or third-party
permissions. When personal stories are involved, invite the user to choose
what may be disclosed.

## Runtime feasibility

For each scene estimate speech, visual action and transition time separately.
For each proposed narration passage, count the words in the **actual quoted narration text**, not a paraphrase or outline. State the convention (for example, whitespace-delimited tokens with punctuation attached; hyphenated terms count as one), the exact count, the assumed or measured speaking rate in words per minute, and the calculation `seconds = word_count / words_per_minute * 60`. Recheck arithmetic when the text changes. If a script is not yet written, label the count as a target, never an actual count. Narration duration must be based on an explicitly stated or measured speaking rate; do not present a calculated duration as verified playback. Leave room for silence.
Flag when the requested content cannot reasonably fit the target runtime.

## Escalation

When approval is missing, stop at the current gate and ask for it.
When constraints conflict, identify the narrowest conflict and request
clarification before changing approved material.
