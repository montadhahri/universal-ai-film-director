# Generator and execution checklist

Identify the actual model/provider and access before claiming support. Verify duration limits, aspect ratios, allowed image references, motion controls, generation output form, audio, account requirements, restrictions, costs and retries from official documentation or observed tool metadata.

Every **shot packet** includes: project ID, shot ID/revision, exact approved storyboard and Visual Bible revision references, global start/end timing, source-vs-edit timing and transition overlap where relevant, upstream/downstream shot dependency IDs, approved visual continuity anchors, optional real image references with provenance, clip generation prompt, negative constraints, audio instructions as a separate section and edit/transition instructions. Mark missing approval or reference IDs UNVERIFIED rather than inventing them. A generator packet must not silently alter locked timing or anchors.

Use execution evidence states: PLAN_ONLY (packet only; no job), BLOCKED_NO_PROVIDER (no verified authorized execution route), REQUESTED (provider accepted an actual submission; record job ID/receipt), GENERATED (provider reports successful completion; record completion evidence, not assumed media inspection), RETRIEVED (real output asset obtained and path/ID verified), INSPECTED (real playable media reviewed with method/timecoded observations), FAILED (provider reported failure or an actual attempted operation failed; preserve error and retry/rollback scope). Never advance states based on a planned prompt, presumed provider behavior or a submission alone. A job being submitted is not a playable clip. Separate user authorizations for costs, asset upload, generation and publication. Report provider errors accurately; keep prior approved assets untouched.
